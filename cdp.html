What is Cisco Discovery Protocol (CDP)?

Cisco Discovery Protocol (CDP) is a proprietary Layer 2 protocol developed by Cisco Systems that allows network devices to share information about themselves with other directly connected Cisco devices.

Key Characteristics:

  • Layer 2 Protocol: Operates at the Data Link Layer
  • Cisco Proprietary: Only works between Cisco devices
  • Automatic Discovery: Requires no configuration by default
  • Periodic Updates: Sends advertisements every 60 seconds
  • Neighbor Discovery: Identifies directly connected devices only

CDP Versions

Primary Purposes

  • Network Discovery: Automatically discover neighboring Cisco devices
  • Troubleshooting: Identify connectivity and configuration issues
  • Network Mapping: Build topology maps for documentation
  • Inventory Management: Track device types, versions, and capabilities
  • Protocol Debugging: Verify Layer 2 connectivity

Technical Specifications

Protocol Characteristics

  • Encapsulation: Uses SNAP (Subnetwork Access Protocol)
  • Multicast Address: 01-00-0C-CC-CC-CC
  • DSAP/SSAP: 0xAA (for SNAP)
  • OUI: 00-00-0C (Cisco)
  • Protocol ID: 0x2000

Timing Parameters

Parameter Default Value Description
Advertisement Interval 60 seconds How often CDP packets are sent
Hold Time 180 seconds Time to keep neighbor information

CDP TLV (Type-Length-Value) Fields

TLV Type Value Description
Device ID 0x0001 Hostname of the device
Address 0x0002 Network addresses (IP, IPX, etc.)
Port ID 0x0003 Interface sending the CDP packet
Capabilities 0x0004 Device capabilities (Router, Switch, etc.)
Software Version 0x0005 IOS version and hardware info
Platform 0x0006 Hardware platform information
IP Network Prefix 0x0007 IP network prefix (CDP v2)

Capability Flags

Bit 0: Router Bit 1: Transparent Bridge Bit 2: Source Route Bridge Bit 3: Switch Bit 4: Host Bit 5: IGMP capable Bit 6: Repeater Bit 7: VoIP Phone

Configuration Commands

! Enable CDP globally Router(config)# cdp run ! Enable CDP on interface Router(config-if)# cdp enable ! Disable CDP globally Router(config)# no cdp run ! Disable CDP on interface Router(config-if)# no cdp enable ! Configure timers Router(config)# cdp timer 60 Router(config)# cdp holdtime 180 ! View CDP neighbors Router# show cdp neighbors Router# show cdp neighbors detail ! View CDP interface information Router# show cdp interface

Real-World CDP Applications

1. Network Documentation and Discovery

Scenario:

You're a new network engineer at a company with undocumented network infrastructure. You need to create an accurate network topology.

CDP Solution:

# Connect to core switch show cdp neighbors detail # Example output: Device ID: Router-HQ Entry address(es): IP address: 10.1.1.1 Platform: Cisco 2901, Capabilities: Router Switch IGMP Interface: GigabitEthernet1/0/1, Port ID: GigabitEthernet0/0 Hold time: 156 sec # Use this to map the entire network show cdp neighbors | include Device ID

Benefits:

  • Quick topology discovery without physical cable tracing
  • Identifies device models and capabilities
  • Shows IP addresses and interface connections
  • Helps create accurate network diagrams

2. Troubleshooting Connectivity Issues

Scenario:

Users report connectivity issues between two network segments. You suspect a problem with an intermediate switch.

CDP Troubleshooting Process:

# Check if devices can see each other show cdp neighbors # If neighbor missing, check interface status show cdp interface # Verify CDP is enabled show cdp # Check for duplex mismatches show cdp neighbors detail | include Duplex # Example troubleshooting output: Interface: Fa0/1 is up, line protocol is up Encapsulation ARPA Sending CDP packets every 60 seconds Holdtime is 180 seconds

Common Issues Detected:

  • Physical connectivity problems
  • Duplex/speed mismatches
  • VLAN configuration errors
  • Power over Ethernet issues

3. Network Inventory Management

Scenario:

IT management needs an audit of all network equipment including models, software versions, and capabilities.

CDP Inventory Script:

# Automated inventory collection show cdp neighbors detail | include Device ID|Platform|Software|IP address # Create inventory report Device ID: SW-Floor2 Platform: cisco WS-C2960-24TT-L, Capabilities: Switch IGMP Software version: Cisco IOS Software, Version 12.2(55)SE9 Device ID: AP-Conference Platform: cisco AIR-AP1242AG-A-K9, Capabilities: Switch IGMP Software version: Cisco IOS Software, Version 12.4(25d)JA2

Inventory Data Collected:

  • Device hostnames and models
  • Software versions for patch management
  • IP addresses for management access
  • Device capabilities and roles

4. VoIP Phone Management

Scenario:

Managing hundreds of Cisco IP phones across multiple floors and buildings.

CDP for VoIP Management:

# Find all connected IP phones show cdp neighbors | include Phone # Check phone power consumption show cdp neighbors detail | include Phone|Power # Example phone information: Device ID: SEP001DA2123456 Platform: Cisco IP Phone 7940, Capabilities: Host Phone Interface: FastEthernet0/12, Port ID: Port 1 Power drawn: 6.300 Watts

VoIP Use Cases:

  • Locate specific phones by MAC address
  • Monitor power consumption for PoE planning
  • Verify phone-to-switch connections
  • Troubleshoot voice quality issues

5. Security and Compliance Auditing

Security Considerations:

While CDP is useful, it can be a security risk as it reveals network topology information.

Best Practices:

  • Disable CDP on interfaces facing untrusted networks
  • Use LLDP (IEEE standard) when interoperating with non-Cisco devices
  • Regular audits of CDP-enabled interfaces
  • Monitor for unauthorized devices appearing in CDP tables
# Disable CDP on external interfaces interface GigabitEthernet0/0 no cdp enable # Enable only where needed interface range fa0/1-24 cdp enable

Case Study: Large Enterprise Network

Organization:

Global corporation with 50+ locations, 10,000+ network devices

CDP Implementation:

CDP Security Considerations

⚠️ Security Risks

CDP can expose sensitive network information to potential attackers. Understanding these risks is crucial for proper network security.

Information Disclosure Risks

CDP Reveals:

  • Network Topology: Device connections and layout
  • Device Information: Models, software versions, capabilities
  • IP Addresses: Management and interface addresses
  • Interface Details: Port names, speeds, duplex settings
  • VLAN Information: Native VLANs and trunking details

Attack Scenarios

1. Network Reconnaissance

Attackers can use CDP to map network infrastructure without authorized access.

# Attacker connects unauthorized device # Immediately receives CDP advertisements # Learns network topology and device information show cdp neighbors detail

2. Vulnerability Exploitation

Software version information helps attackers identify vulnerable devices.

# CDP reveals exact IOS versions Software version: Cisco IOS Software, Version 12.2(55)SE9 # Attacker searches for known vulnerabilities in this version

3. Social Engineering

Device hostnames and IP addresses can be used for targeted attacks.

Security Best Practices

1. Selective CDP Deployment

# Disable CDP globally, enable only where needed no cdp run # Enable CDP only on internal links interface range gi0/1-24 cdp enable # Keep CDP disabled on external/DMZ interfaces interface gi0/0 no cdp enable

2. Interface-Level Control

# Disable CDP on access ports interface range fa0/1-48 switchport mode access no cdp enable # Enable only on trunk/management ports interface gi0/1 switchport mode trunk cdp enable

3. Regular Security Audits

# Audit CDP-enabled interfaces show cdp interface # Check for unexpected neighbors show cdp neighbors # Monitor for unauthorized devices show cdp neighbors detail | include Device ID

4. Alternative Protocols

LLDP (Link Layer Discovery Protocol)
  • IEEE 802.1AB standard
  • Vendor-neutral alternative to CDP
  • More granular security controls
  • Better for mixed-vendor environments
# Enable LLDP instead of CDP lldp run interface gi0/1 lldp transmit lldp receive

Compliance and Policy

Organizational CDP Policy Example:

  • Default State: CDP disabled by default on all new devices
  • Internal Use Only: CDP enabled only on internal management networks
  • Documentation: All CDP-enabled interfaces must be documented
  • Review Cycle: Quarterly review of CDP configuration
  • Incident Response: Unauthorized CDP neighbors trigger security investigation

Monitoring and Detection

Automated Security Monitoring

# Script to detect new CDP neighbors #!/bin/bash # Check for new devices in CDP table CURRENT_NEIGHBORS=$(show cdp neighbors | grep "Device ID") if [ "$CURRENT_NEIGHBORS" != "$STORED_NEIGHBORS" ]; then echo "New CDP neighbor detected - investigate immediately" # Send alert to security team fi
