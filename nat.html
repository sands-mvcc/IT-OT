What is NAT/PAT?

Network Address Translation (NAT) with Port Address Translation (PAT) is a networking technique that allows multiple devices on a private network to share a single public IP address when accessing the internet.

→
Web Server

Key Concepts

  • Private IP Addresses: RFC 1918 addresses (10.x.x.x, 172.16-31.x.x, 192.168.x.x)
  • Public IP Address: Internet-routable address assigned by ISP
  • Port Translation: Using different ports to distinguish connections
  • Translation Table: Maintains mapping between internal and external addresses

NAT/PAT Process

  1. Internal device sends packet with private IP and random source port
  2. NAT router replaces source IP with public IP and assigns new port
  3. Router stores translation in NAT table
  4. External server responds to public IP and assigned port
  5. Router looks up translation and forwards to original internal device

Workplace Applications and Examples

1. Corporate Office Network

Scenario: 500-employee company with single public IP from ISP

  • Challenge: Enable internet access for all employees
  • Solution: NAT/PAT router with 10.0.0.0/8 internal network
  • Implementation: Cisco ASA firewall with PAT configuration
  • Benefits: Cost savings, security through obscurity, centralized internet control
Configuration Example (Cisco):
interface GigabitEthernet0/0
 ip address 203.0.113.10 255.255.255.248
 ip nat outside
interface GigabitEthernet0/1
 ip address 10.0.1.1 255.255.255.0
 ip nat inside
ip nat inside source list 1 interface GigabitEthernet0/0 overload
access-list 1 permit 10.0.0.0 0.255.255.255

2. Home Office Setup

Scenario: Remote worker with multiple devices

  • Devices: Laptop, desktop, phone, IoT devices
  • ISP Assignment: Single dynamic public IP
  • Router: Consumer-grade with automatic NAT/PAT
  • Network: 192.168.1.0/24

3. Data Center DMZ

Scenario: Web servers behind NAT for security

  • External Access: Port forwarding for HTTP/HTTPS
  • Internal Servers: Database servers with private IPs
  • Security: Stateful inspection and logging
Port Forwarding Example:
ip nat inside source static tcp 192.168.100.10 80 203.0.113.10 80
ip nat inside source static tcp 192.168.100.10 443 203.0.113.10 443

4. Troubleshooting Common Issues

Best Practices and Considerations

  • Port Exhaustion: Monitor active connections (65,535 port limit)
  • Session Timeouts: Configure appropriate timeout values
  • Logging: Enable NAT logging for security and troubleshooting
  • Performance: Consider NAT hardware acceleration for high throughput
  • IPv6 Transition: Plan for IPv6 implementation to reduce NAT dependency
  • Security: NAT is not a security feature - use proper firewalls
