IEC 62443 Framework Overview

IEC 62443 is a comprehensive series of international standards specifically designed to secure Industrial Automation and Control Systems (IACS) throughout their entire lifecycle.
Purpose
Provides cybersecurity guidance for industrial automation and control systems, addressing unique OT requirements different from traditional IT security.
Development
Developed jointly by ISA99 committee and IEC TC65 WG10, originally known as ISA99 standards, now internationally recognized as IEC 62443.
Scope
Covers all aspects of IACS security including risk assessment, secure development, system design, and ongoing maintenance across 20+ industry sectors.
Approach
Takes a holistic, risk-based approach emphasizing defense-in-depth strategies, zone segmentation, and shared responsibility among stakeholders.
Key Principle: Shared responsibility among asset owners, product suppliers, integrators, and service providers to ensure comprehensive cybersecurity coverage.

Framework Structure

The IEC 62443 series is organized into four main categories, each addressing different aspects of industrial cybersecurity:

1. General (IEC 62443-1)
Foundational concepts, terminology, and models used throughout the series. Defines the seven foundational requirements and basic security concepts.
2. Policies & Procedures (IEC 62443-2)
Security management systems, organizational requirements, and cybersecurity program implementation for asset owners and service providers.
3. System (IEC 62443-3)
System-level security requirements, risk assessment processes, zones and conduits architecture, and technical security controls.
4. Component (IEC 62443-4)
Secure development lifecycle requirements and technical security requirements for individual IACS components and products.
Horizontal Standard: IEC has approved 62443 as a "horizontal standard," meaning it must be used as the foundation for OT security requirements across all industry sectors.

Zones
Groups of physical or logical assets sharing common security requirements with clearly defined boundaries. Enable targeted security controls based on criticality and risk.
Conduits
Communication paths between zones with security controls to manage data flow. Include firewalls, encryption, and access controls to protect inter-zone communication.
Segmentation Benefits
Limits attack propagation, enables targeted security measures, supports compliance requirements, and provides clear security boundaries.
Design Principles
Based on risk assessment, aligns with Purdue Model levels, supports defense-in-depth, and enables scalable security architecture.

Security Levels (SL)

Security Levels define the confidence that systems, zones, or conduits are free from vulnerabilities and function as intended, based on different threat scenarios.

SL-0
No Protection Required
No special cybersecurity protection or requirements needed.
SL-1
Protection Against Unintentional Misuse
Guards against casual or coincidental violations, unintentional human errors, and non-malicious mistakes.
SL-2
Protection Against Intentional Misuse (Simple Means)
Defends against threats from individuals with low motivation, basic resources, and simple tools and techniques.
SL-3
Protection Against Sophisticated Attacks
Shields against intentional misuse using sophisticated means with moderate resources, automation-specific knowledge, and moderate motivation.
SL-4
Protection Against Advanced Threats
Covers protection against intentional misuse using sophisticated means with extensive resources, automation-specific knowledge, and high motivation (nation-state level threats).
Security Level Vector: Each zone or conduit has a seven-element vector representing the security level for each foundational requirement, allowing granular security tailoring.

Seven Foundational Requirements

The seven foundational requirements (FRs) form the core security framework that applies across all IEC 62443 standards:

FR1: Identification and Authentication Control (IAC)
Ensures reliable identification and authentication of all users (humans, software processes, devices) before granting access to IACS resources.
FR2: Use Control (UC)
Prevents unauthorized actions by verifying appropriate privileges before allowing users to perform specific functions or access resources.
FR3: System Integrity (SI)
Protects against unauthorized modifications to system data, software, and configurations by unauthorized persons or systems.
FR4: Data Confidentiality (DC)
Prevents unauthorized disclosure of sensitive information through encryption and access controls on communication channels and data repositories.
FR5: Restricted Data Flow (RDF)
Controls and limits data flow between zones and external networks through segmentation, conduits, and network access controls.
FR6: Timely Response to Events (TRE)
Ensures collection, reporting, and preservation of security event evidence to enable timely detection and corrective actions.
FR7: Resource Availability (RA)
Maintains device and system functionality during normal operations and resilience against denial-of-service attacks and other availability threats.

Component Requirements

The Component (Part 4) standards define requirements for secure development and technical capabilities of IACS components:

IEC 62443-4-1
Secure Development Lifecycle (SDL) requirements for product suppliers. Covers design, coding, testing, patch management, and end-of-life processes.
IEC 62443-4-2
Technical security requirements for IACS components including embedded devices, network components, host devices, and software applications.
