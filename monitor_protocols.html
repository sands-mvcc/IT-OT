SNMP
SNMP
Simple Network Management Protocol

🎯 Purpose & Mission

SNMP provides standardized network device monitoring and management capabilities across both IT and OT infrastructure, enabling centralized visibility into device health, performance metrics, and operational status.

Key Capabilities

📊 Real-time device monitoring
⚡ Trap-based event notifications
📈 Performance metric collection
🔧 Configuration management support
🌐 Cross-vendor device compatibility
📋 Standardized MIB (Management Information Base)

SNMP Query Example:

snmpget -v2c -c public 192.168.1.100 1.3.6.1.2.1.1.5.0
# Returns: system.sysName.0 = STRING: "Industrial-Switch-01"

snmpwalk -v2c -c public 192.168.1.100 1.3.6.1.2.1.2.2.1.10
# Returns interface traffic statistics
SLOG
Syslog
System Logging Protocol

🎯 Purpose & Mission

Syslog provides standardized logging and event collection from network devices and systems, enabling centralized security monitoring, compliance reporting, and operational troubleshooting across IT/OT environments.

Key Capabilities

📝 Standardized log message format
🏢 Centralized log collection
⚠️ Severity level classification
⏰ Precise time-stamped events
🔒 SIEM integration support
📊 Real-time log streaming

Syslog Message Format:

<Priority>Timestamp Hostname Tag: Message

Example:
<166>Oct 22 10:52:01 plc-server-01 modbus[1234]: Connection established to HMI client 192.168.1.50
<165>Oct 22 10:52:15 sensor-gateway-02 mqtt[5678]: Temperature sensor offline - Device ID: TEMP_001
MQTT
MQTT
Message Queuing Telemetry Transport

🎯 Purpose & Mission

MQTT enables efficient, lightweight messaging for IoT and industrial devices with minimal bandwidth and power requirements, using a publish/subscribe model perfect for distributed sensor networks and real-time data streaming.

Key Capabilities

📡 Publish/Subscribe messaging model
⚡ Ultra-lightweight protocol overhead
🎯 Quality of Service (QoS) levels
💾 Retained message support
💔 Last Will and Testament feature
🔄 Persistent session support

MQTT Topic Structure:

factory/line-1/temperature          → 24.5°C
factory/line-1/pressure             → 2.1 bar
factory/line-1/status               → "running"
factory/line-2/vibration/sensor-01  → 0.002 mm/s
factory/alerts/critical             → "Motor overheating on Line 1"

# QoS Levels:
# QoS 0: At most once delivery (fire and forget)
# QoS 1: At least once delivery (acknowledged)
# QoS 2: Exactly once delivery (assured)
REST
RESTful APIs
REST with JSON/XML Data Formats

🎯 Purpose & Mission

RESTful APIs provide modern, web-standard interfaces for integrating enterprise systems with operational technology data and services, enabling scalable, platform-independent communication using standard HTTP methods.

Key Capabilities

🌐 HTTP-based stateless communication
📋 Standard data formats (JSON/XML)
🔄 CRUD operations support
🔧 Platform-independent integration
📈 Highly scalable architecture
🔒 OAuth/JWT authentication support

REST API Example:

# Get sensor data
GET /api/v1/sensors/temperature/line-1
Response: {
  "sensor_id": "TEMP_LINE1_001",
  "value": 24.5,
  "unit": "celsius",
  "timestamp": "2025-07-05T10:30:00Z",
  "status": "normal"
}

# Update device configuration
PUT /api/v1/devices/plc-001/config
{
  "sampling_rate": 1000,
  "alarm_threshold": 85.0,
  "enabled": true
}
