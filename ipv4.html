IPv4 Overview & Definition

Internet Protocol Version 4 (IPv4) is the fourth version of the Internet Protocol and remains the most widely used version for routing internet traffic today, despite the ongoing deployment of IPv6.

Historical Background

IPv4 was first deployed for production use on SATNET in 1982 and on ARPANET in January 1983. It was developed as part of the Defense Advanced Research Projects Agency (DARPA) internet project and has been the backbone of internet communications for over four decades.

Key Characteristics

  • 32-bit addressing: Provides 4,294,967,296 (2³²) unique addresses
  • Connectionless protocol: Each packet is treated independently
  • Best-effort delivery: No guarantee of packet delivery, order, or error-free transmission
  • Hierarchical addressing: Supports network and host portions
  • Fragmentation support: Can split large packets for transmission

Current Status

While IPv4 continues to handle most internet traffic, address exhaustion has led to the development and gradual deployment of IPv6. Techniques like Network Address Translation (NAT) and Classless Inter-Domain Routing (CIDR) have helped extend IPv4's usability.

Fun Fact: The total IPv4 address space could theoretically assign one IP address to every square meter of Earth's surface about 84 times over!

32-Bit Address Structure

IPv4 addresses consist of 32 bits, typically represented as four 8-bit octets in dotted decimal notation.

Dotted Decimal Notation

Each octet represents 8 bits and can have values from 0 to 255 (2⁸ = 256 possible values). This human-readable format makes IP addresses easier to remember and work with than their binary equivalents.

Binary: 11000000 10101000 00000001 00000001 Decimal: 192 168 1 1 Address: 192.168.1.1

Network vs. Host Portions

IPv4 addresses are divided into network and host portions:

  • Network Portion: Identifies the specific network
  • Host Portion: Identifies the specific device within that network
  • Subnet Mask: Determines the boundary between network and host portions
The division between network and host portions is flexible and determined by the subnet mask, enabling efficient address allocation and routing.

IPv4 Address Classes

Traditional IPv4 addressing used a classful system that divided the address space into five classes (A through E) based on the first few bits of the address.

Modern Classless Addressing (CIDR)

The classful system was largely replaced by Classless Inter-Domain Routing (CIDR) in 1993. CIDR uses variable-length subnet masking (VLSM) for more efficient address allocation.

CIDR Notation Examples:

  • 192.168.1.0/24 - Network with 24 network bits, 8 host bits (254 hosts)
  • 10.0.0.0/8 - Network with 8 network bits, 24 host bits (16,777,214 hosts)
  • 172.16.0.0/16 - Network with 16 network bits, 16 host bits (65,534 hosts)

Benefits of CIDR over Classful Addressing

  • Efficient Address Utilization: Reduces wasted addresses
  • Flexible Subnetting: Custom network sizes
  • Route Aggregation: Reduces routing table size
  • Hierarchical Addressing: Better network organization

IPv4 Special Addresses

Several IPv4 address ranges are reserved for special purposes and are not routable on the public internet.

🏠 Private Addresses (RFC 1918)

Class A: 10.0.0.0/8
Class B: 172.16.0.0/12
Class C: 192.168.0.0/16

Purpose: Internal network use, not routable on internet. Enables NAT and conserves public addresses.

🔄 Loopback Addresses

Range: 127.0.0.0/8
Common: 127.0.0.1 (localhost)

Purpose: Self-referencing for testing and local services. Traffic never leaves the host.

📡 Multicast Addresses

Range: 224.0.0.0/4
Notable: 224.0.0.1 (All Hosts)
224.0.0.2 (All Routers)

Purpose: One-to-many communication, streaming media, routing protocols.

🔗 Link-Local Addresses

Range: 169.254.0.0/16

Purpose: Automatic addressing when DHCP fails. Local segment communication only.

📋 Documentation Addresses

Ranges:
192.0.2.0/24 (TEST-NET-1)
198.51.100.0/24 (TEST-NET-2)
203.0.113.0/24 (TEST-NET-3)

Purpose: Safe for documentation and examples.

📢 Broadcast Addresses

Limited: 255.255.255.255
Directed: Network + all host bits set

Purpose: Send to all hosts on network or subnet.

Special Address Usage Examples

# Ping localhost (loopback test) ping 127.0.0.1 # Check for link-local addresses (Windows) ipconfig | findstr "169.254" # Multicast ping to all hosts on local network ping 224.0.0.1
Important: These special addresses serve critical networking functions and should never be assigned to regular host interfaces on the public internet.

IPv4 Packet Header Format

The IPv4 header contains essential information for packet routing and delivery. It consists of a fixed 20-byte section plus optional fields.

Header Field Descriptions

Field Size Description Values/Notes
Version 4 bits IP protocol version Always 4 for IPv4
IHL 4 bits Internet Header Length 5-15 (×4 bytes), minimum 20 bytes
Type of Service 8 bits QoS and priority information DSCP (6 bits) + ECN (2 bits)
Total Length 16 bits Total packet size (header + data) 20-65,535 bytes
Identification 16 bits Unique packet identifier Used for fragmentation/reassembly
Flags 3 bits Fragmentation control Reserved(0), DF, MF
Fragment Offset 13 bits Position of fragment in original packet In 8-byte units
Time to Live 8 bits Maximum hops before discard 0-255, decremented by each router
Protocol 8 bits Next-level protocol identifier 1=ICMP, 6=TCP, 17=UDP
Header Checksum 16 bits Error detection for header Recalculated at each hop
Source Address 32 bits Sender's IP address May be modified by NAT
Destination Address 32 bits Receiver's IP address Target of the packet
Options 0-320 bits Optional features Security, routing, timestamps

Key Header Concepts:
